## Обзор проекта

**Web1C Shop** — многопользовательская платформа интернет-магазина с полной интеграцией с 1С:Управление Торговлей 11.5 через OData.

### Ключевые возможности

✅ **Синхронизация с 1С:**
- Товары и группы товаров
- Изображения товаров (загрузка на платформу)
- Остатки на складах
- Цены (розничные, оптовые)
- Партнёры (контрагенты)
- Заказы клиентов
- Реализации (статусы заказов)

✅ **Ролевая модель:**
- Администратор — полное управление системой
- Партнёр — B2B клиент с историей заказов
- Покупатель — розничный клиент с упрощённым интерфейсом

✅ **Документы:**
- Печать накладной в PDF с УИД и штрих-кодом
- Выгрузка в Excel (XLSX)
- Нумерация документов из 1С

## Быстрый старт

### Шаг 1: Подготовка

```bash
cd D:\Work\Web1C

# Скопируйте файл окружения
copy .env.example .env
```

### Шаг 2: Настройка переменных окружения

Откройте `.env` и укажите параметры:

```ini
# 1C:UT OData Configuration
ONEC_URL=http://your-1c-server:8080/hs/odata
ONEC_USER=odata_user
ONEC_PASSWORD=your_password

# Database
POSTGRES_PASSWORD=web1c_secret_change_in_production

# JWT Secret (сгенерируйте случайную строку)
JWT_SECRET=your_secret_key_here

# Application
APP_URL=http://localhost
```

### Шаг 3: Запуск контейнеров

#### Production режим:
```bash
docker compose up -d --build
```

#### Development режим (с hot-reload):
```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up
```

### Шаг 4: Инициализация базы данных

```bash
# Применение миграций
docker compose exec app npx prisma migrate deploy

# Генерация клиента Prisma
docker compose exec app npx prisma generate

# Seed данных (создание админа)
docker compose exec app npx prisma db seed
```

### Шаг 5: Первый вход

- **URL:** http://localhost
- **Email:** `admin@web1c.local`
- **Пароль:** `admin123`

⚠️ **ВАЖНО:** Измените пароль администратора после первого входа!

## Настройка 1С:УТ 11.5

### 1. Публикация OData на веб-сервере

1. Откройте 1С:УТ 11.5 в режиме **Конфигуратор**
2. Перейдите: **Администрирование** → **Публикация на веб-сервере**
3. Нажмите **Добавить**
4. Выберите тип публикации: **OData**
5. Укажите параметры:
   - **Имя публикации:** `odata`
   - **Путь:** `/hs/odata`
   - **База данных:** ваша база УТ 11.5
6. Нажмите **Опубликовать**

### 2. Настройка прав доступа

Создайте пользователя 1С с правами на следующие объекты:

| Объект 1С | Тип | Права |
|-----------|-----|-------|
| `Catalogs.Products` | Справочник | Чтение |
| `Catalogs.ProductGroups` | Справочник | Чтение |
| `Catalogs.Partners` | Справочник | Чтение |
| `Catalogs.Warehouses` | Справочник | Чтение |
| `Documents.SalesOrder` | Документ | Чтение, Запись |
| `Documents.Realization` | Документ | Чтение |
| `InformationRegisters.Prices` | Регистр | Чтение |
| `InformationRegisters.Stocks` | Регистр | Чтение |
| `InformationRegisters.ProductImages` | Регистр | Чтение |

### 3. Проверка подключения

Откройте в браузере:
```
http://your-1c-server:8080/hs/odata/$metadata
```

Должна отобразиться XML-схема метаданных OData.

### 4. Настройка параметров синхронизации в 1С

Для корректной работы синхронизации убедитесь:

1. **Номенклатура** имеет заполненные реквизиты:
   - Наименование полное
   - Артикул
   - Группа (для категоризации)
   - Единица измерения

2. **Контрагенты** имеют:
   - ИНН (обязательно для поиска)
   - КПП (при наличии)
   - Наименование полное
   - Контактная информация

3. **Цены** зарегистрированы в регистре `Prices`

4. **Остатки** доступны в регистре `Stocks`

## Синхронизация с 1С

### Типы синхронизации

#### 1. Полная синхронизация
Загружает все данные из 1С:
- Группы товаров
- Товары
- Партнёры
- Остатки
- Заказы

#### 2. Инкрементальная синхронизация
Загружает только изменённые данные (по дате модификации)

#### 3. Выборочная синхронизация
Только указанные сущности (товары, партнёры и т.д.)

### Процесс синхронизации

```
1. Создание сессии синхронизации
   ↓
2. Подключение к 1C OData
   ↓
3. Загрузка данных (пакетами по 1000 записей)
   ↓
4. Upsert в PostgreSQL
   ↓
5. Логирование результатов
   ↓
6. Обновление статуса сессии
```

### Мониторинг синхронизации

1. Откройте `/admin/sync`
2. Выберите тип синхронизации
3. Нажмите кнопку запуска
4. Отслеживайте прогресс в реальном времени

### Логи синхронизации

```bash
# Логи worker
docker compose logs -f worker

# Просмотр сессий через API
GET /api/admin/sync/sessions
```

## Устранение проблем

### Ошибка подключения к 1С

**Симптомы:**
- "Не удалось подключиться к 1С"
- Таймаут соединения

**Решение:**
1. Проверьте доступность 1С:
   ```bash
   curl http://1c-server:8080/hs/odata/$metadata
   ```
2. Убедитесь в правильности учётных данных
3. Проверьте права пользователя 1С
4. Убедитесь, что OData публикация активна

### Ошибки синхронизации

**Симптомы:**
- Частичная синхронизация
- Ошибки в логах

**Решение:**
1. Откройте `/admin/sync` для просмотра истории
2. Проверьте логи worker:
   ```bash
   docker compose logs worker
   ```
3. Убедитесь, что структура 1С соответствует ожидаемой
4. Проверьте наличие обязательных реквизитов

### Проблемы с базой данных

**Симптомы:**
- Ошибки подключения к PostgreSQL
- Ошибки миграций

**Решение:**
1. Проверьте статус контейнера:
   ```bash
   docker compose ps db
   ```
2. Перезапустите базу:
   ```bash
   docker compose restart db
   ```
3. Примените миграции заново:
   ```bash
   docker compose exec app npx prisma migrate deploy
   ```

### Проблемы с Redis

**Симптомы:**
- Ошибки очередей
- Worker не обрабатывает задачи

**Решение:**
1. Проверьте статус Redis:
   ```bash
   docker compose exec redis redis-cli ping
   ```
2. Перезапустите Redis:
   ```bash
   docker compose restart redis
   ```
